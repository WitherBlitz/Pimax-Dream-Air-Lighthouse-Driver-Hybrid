# Dream Air Lighthouse 1.0 experimental stability fork

User intent: preserve sboys3 driver features and improve inconsistent small jumps, runaway drift, and occasional gray screens in Gorilla Tag. Setup: Dream Air Lighthouse, firmware 1.0.3, two 1.0 stations with sync cable in A/b modes. The project is an isolated fork of GPLv2 CustomHeadsetOpenVR 1.3.0, commit 21185da63a9e4307ae876b3702a43a43044d451c. User AGENTS.md preauthorizes approval prompts and requests automatic inline continuation.

Evidence: existing settings have forceTracking=true; SteamVR logs show HMD out-of-bounds reset, inadequate bootstrap samples, optical loss, and `Base [station serial omitted] axis 0 appears to have failed`. These do not establish a single root cause. Restart success does not exclude sync, optical, firmware, or intermittent hardware faults. Do not claim the hardware issue or tracking is fixed.

Architecture: retain the entire upstream rendering, distortion, eye tracking, shader, settings, and GUI architecture. Add a small independent, tested pose guard at the existing driver-host pose callback. Register the actual Dream Air Lighthouse device index during successful activation, rather than assume device 0. Controllers, base stations, other HMDs, and rotation-only tracking bypass the new filter. Use upstream's documented private-only released helper when using Pimax Play; OpenPort can operate without it. This fork does not modify headset firmware, station firmware, calibration geometry, raw optical decoding, or the closed-source Lighthouse solver.

Required behavior:
- Enabled guard takes precedence over this module's forceTracking for the registered HMD; never upgrade invalid/fallback/disconnected poses to valid 6DoF. Both shared force flags must remain false with the upstream private helper, which can also hook poses; package profiles enforce the initial setting and diagnostics expose later requests.
- Finite checking includes positions, velocities, accelerations, timestamps, all three quaternion rotations, and coordinate transforms. Normalize usable quaternions and reject corrupt/zero ones; output finite invalid poses rather than propagate NaN/Inf.
- Reject impossible frame-to-frame position/rotation jumps, and excessive reported velocities. Default limits: 8 m/s position delta, 35 rad/s angular delta, 35 mm position slack, 8 degrees rotation slack, 12 m/s reported velocity, 50 rad/s reported angular velocity, 250 ms pose-time offset, 100 ms callback gap. These are configurable conservative bounds, not measured hardware specifications.
- After loss, corrupt data, timestamp reversal, a long gap, or an outlier, require three mutually consistent valid samples before adopting a new trajectory. A one-frame jump followed by return to the previous trajectory should recover without drifting toward the spike. Coordinate-frame changes reset the history without interpolating between universes. Do not indefinitely freeze a pose while labelling it valid. Slow plausible drift cannot be distinguished from movement by this layer.
- Default Guard profile has smoothing disabled, suitable for fast games. Optional adaptive position/quaternion filtering uses bounded cutoffs, shortest-arc quaternion interpolation, actual sample intervals, and clears history on discontinuities. Baseline disables the guard and forceTracking to enable comparison.
- Runtime configuration is validated/clamped and read via a mutex-protected snapshot; pose callbacks perform no disk I/O. Emit thread-safe counters and last decision in a separate diagnostic file so an upstream private helper cannot overwrite it.
- Ship a Windows x64 binary, original upstream GUI, license and notices, full corresponding public source with pinned dependencies, build/test scripts, diagnostics recorder, profile switcher, stopped-runtime installer, and exact rollback of replaced driver/settings. Do not disrupt an active VR session to test an experimental binary. Stage the ready package and test its installer against a sandbox.
- Installer must back up existing files before writes, refuse while vrserver/vrcompositor/GUI runs, preserve visual settings and distortion files, never mutate Lighthouse databases, and support Pimax Play or OpenPort. No external publication or messaging.

Validation: native C++ tests against actual OpenVR DriverPose_t for invalid states, corruption, jumps, recovery, legitimate fast movement, frame changes, timing, quaternion sign/wrap, smoothing behavior, and configuration limits. Compile full Release x64 driver with SkipPostBuild=true. Read-only baseline recording through official OpenVR APIs; sandbox install/rollback tests; fresh review. Hardware/game validation remains pending until user tries the staged build. Feature parity is inherited public code, not a claim of hardware-verified parity or a fully independent replacement for proprietary Pimax/Valve components.
