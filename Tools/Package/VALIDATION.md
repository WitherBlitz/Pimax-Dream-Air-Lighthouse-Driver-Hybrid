# Validation — Dream Air LH1 0.3.2 experimental

Built locally on 2026-10-10 from sboys3 CustomHeadsetOpenVR 1.3.0, commit `21185da63a9e4307ae876b3702a43a43044d451c`, with its pinned submodules. The public source and build scripts are in `Source.zip`; exact binary hashes and dependency revisions are in `PROVENANCE.json` and `SHA256SUMS.txt`.

## Completed checks

- **0.3.2 tracking correction, 2026-10-10:** the user's successful 0.3.1 capture contained **368/1917 invalid HMD samples (19.2%)**. A 30-second Baseline comparison then contained **0/1914 invalid samples**; a repeat 20-second Guard comparison contained **168/1272 invalid samples (13.2%)**. During the repeat, the driver's source-invalid count did not increase, while stale-time rejections increased by 966 and reacquisition frames by 1004. This identifies an added guard failure, without establishing that every earlier tracking issue had the same cause. The live profile was returned to Baseline after the repeat.
- Filter history previously used callback arrival plus OpenVR's relative prediction offset. Changes in that offset could turn chronological callbacks into apparent time reversals or gaps. History now uses callback arrival time and preserves the accepted pose's current prediction fields. Baseline also keeps reporting current sample/source/output statistics instead of freezing them when filtering is disabled.
- **Six new native regressions failed before correction (35/41 passed), then all 41/41 passed.** They cover varying/repeated estimated pose times, false gaps from offset changes, and valid/invalid/forced-valid Baseline diagnostics. Existing real callback reversal, gap, loss, jump, recovery, smoothing and device-selection checks remain passing. The full 0.3.2 build passed **41/41 pose, 50/50 floor, 10/10 launcher and 3/3 isolated elevation-host cases**. The host suite deliberately prints a simulated rollback error in its failure-propagation case; the suite passed.
- A fresh read-only reviewer found no actionable Critical, Important or Minor defects in the timestamp/statistics changes. Concurrent callback arrival ordering and the policy for exactly duplicated arrival timestamps remain inherited limitations, recorded in the source verification ledger.
- The initial failed diagnostic attempt occurred with SteamVR closed. Its recorder correctly refused to start a background VR server, then the script saved available logs and reported capture failure. The user's subsequent capture with SteamVR running succeeded.

## Still requiring headset testing

The user installed and ran the previous `1.3.0-dreamair-lh1.1-experimental` OpenPort driver; the captures above measured that build. **The corrected `1.3.0-dreamair-lh1.2-experimental` DLL has not yet been loaded/tested at packaging time.** Its tracking improvement, game compatibility, motion latency and complete inherited feature behavior still require headset testing. Passing native tests or a stationary old-driver Baseline capture does not establish those outcomes.

Floor apply/restore through the real OpenVR chaperone service is also **unverified**. It was exercised through a simulated runtime with real durable backup files. Floor behavior is unchanged in this update. Games that do not use SteamVR's standing origin may ignore its floor height.

This build uses the existing Pimax/Valve Lighthouse decoder. It adds pose validation and recovery handling; it cannot recover missing laser sweeps or distinguish every plausible slow drift from real movement. Rejected data is invalid and may cause a gray screen. Optional filtering adds delay. Compare corrected Guard with Baseline while recording; remain on Baseline in the old 0.3.1 build.

Existing logs contain optical-sample loss, bootstrap failures, HMD out-of-bounds resets, and `Base 3858A002 axis 0 appears to have failed`. These warrant investigation but do not establish a hardware defect. The previous installed driver had `forceTracking=true`, which can conceal source loss. All supplied profiles disable both force-tracking flags; leave them disabled because the separate Play helper can also intercept poses.

Inherited upstream shutdown behavior and unavailable private-helper internals remain outside this change. Keep the installer backup and use `Rollback.cmd` if testing reveals a regression.
